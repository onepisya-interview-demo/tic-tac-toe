## 7. MINOR / FINDING 清单（按严重度）

### MINOR-F1：ux-qa UX_STRICT=1 模式 1/9 场景失败（不阻断）

**现象**：`tests/qa/ux-qa.mjs` `UX_STRICT=1` 下 `play-win` 场景 strictFailure = "winning cells must expose the win-glow animation"。

**根因**：strict 检查要求 `[data-testid^="cell-"] .win-glow` count >= 3。ranked 模式胜局后 `PlayController` 立即 `router.replace('/result')`，4xx ms 内 board 已被卸载，`.win-glow` span 随之消失。

**判定**：⚠️ pre-existing（HEAD ~79c4117 之前已存在，与本次波 A/B 改动无关；Cell.tsx / Board.tsx / BoardGrid.tsx 全部不在 79c4117..2321f04 文件面内）。

**建议**：把 `result-after-win` 之前的 board 截图收紧 300-500ms，或者 strict 检查改在 `result-after-win` 场景断言（该场景已 PASS）。

### MINOR-F2：控制字符 \x01 名走的是 JSON 解析失败 400 而非 validator 422（不阻断）

**现象**：`curl -d '{"name":"abc\x01def"}'` 返回 HTTP 400（坏 JSON），而非 validator 的 422。

**根因**：shell + curl 把 `\x01` 直接塞进 JSON 字符串，触发 Node `request.json()` 抛 SyntaxError → 400。

**判定**：⚠️ pre-existing（PUT handler 设计如此：JSON 解析失败 → 400；语义校验失败 → 422）。

**建议**：无；UI 永远无法构造 \x01 输入（input 元素的 `pattern` + `validateName` 已过滤）。

### MINOR-F3：sync-qa step03 stale DB FAIL（探针工艺）

**现象**：同 DB 上跑 sync-qa 第二次，step03 期望 server xWins=1，实测 2（因 server 已累加 1）。

**根因**：sync-qa.mjs 不重置 server 端 syncprobe-A 行（无 DELETE endpoint 也不调用 reset）。

**判定**：⚠️ probe hygiene（应用代码正确：每次 POST 累加 1 是 server-authoritative 语义）。

**建议**：sync-qa.mjs 开头 `await page.request.delete(${BASE}/api/solo-stats?name=syncprobe-A)` 或加 reset helper。

### MINOR-F4：3 处 auto-POST 重复（follow-up 抽象）
