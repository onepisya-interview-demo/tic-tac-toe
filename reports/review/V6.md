### 3.2 W2 死线激活正确性

**结论：PASS**

- **handleConfirm 失败/放弃路径确实不 dispatch**：`SyncConfirmDialog.handleConfirm` 仅在 `runMergeSequence()` 成功 resolve 后才调 `onConfirm?.(trimmed)` + `onAfterConfirm?.()`（components/SyncConfirmDialog.tsx:194-203）；throw 路径走 `catch (e) { setError(...) } finally { setBusy(false) }`，永不调 onConfirm → `HomeDialogMount.handleConfirm` 永不到达 → `dispatchEvent` 永不触发。reject 路径走 `SyncConfirmDialog` 的 `onReject` prop → `HomeDialogMount.handleReject` 只 `setOpen(false)` + `writeDeclinedPending(pendingSnapshot)`，零 dispatch。

- **focus refetch 有 in-flight 守卫**：`ticketRef` 模式——每次 refetch 创建新 ticket `{ cancelled: false }` 并赋给 ref，旧 ticket 被标 `cancelled = true`；`.then((r) => { if (ticket.cancelled) return; ... })` 用 closure 捕获「自己 ticket」的 cancelled 标志而非全局标志，确保 focus-during-fetch 不会用旧响应覆盖新响应。`setState({ kind: 'loading' })` 在 refetch 起始——新 refetch 总把 UI 重置为 loading 态，与 React 19 推荐的「fetch always sets loading before await」契约一致。

### 3.4 W4 折叠态水合安全

**结论：PASS**

- **hydrate 前骨架**：components/PlayerNameForm.tsx line 158-167 `if (!hydrated) return <div>...skeleton</div>`。`hydrated` state 在 mount 后置 true（line 96 useEffect），SSR 首帧与水合前均显形骨架——SSR 永不读 localStorage。
- **反向 hydration 保留**：line 86-95 useEffect 读 localStorage `ttt.player.name.v1`，若 store 空 + localStorage 有值则 `setStoreName(stored)` + `setName(stored)`。这是 OnlineStatsCard 在 home-return 路径上能立即 fetch 的前提（W3 contract）。
- **折叠判定不会在 SSR 首帧读 localStorage**：`hasSaved = playerName !== null && playerName.length > 0` 仅依赖 store（line 173），`folded = hasSaved && !editing` 同理——纯派生。`editing` 是 useState，初值 false。SSR 首帧：playerName 为 null（store 未水合）→ hasSaved=false → folded=false → 显形 !hasSaved 分支（input + 保存）。水合后：useEffect 触发反向 hydration → setStoreName(stored) → store 更新 → re-render → hasSaved=true, editing=false → folded=true → 折叠分支显形。**关键**：折叠判定不读 localStorage，反向 hydration 是单向的 store→setStoreName，零 SSR-readlocalStorage 反模式。
