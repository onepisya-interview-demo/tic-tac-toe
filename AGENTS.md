# Contribution Guidelines

This block is **not** regenerated by `next dev`; the BEGIN/END markers
above delimit the auto-emitted region and below delimit the project-owned
contribution policy. Anything inside the project-owned region is
maintained by humans/agents and should not be edited by the upstream
emitter.

If you are an AI agent or a human contributor, the policy you need lives
here — no need to leave the repo to find it.

## Commit convention

We follow [Conventional Commits](https://www.conventionalcommits.org/)
with a WHAT/WHY/HOW body in the spirit of the
[`commit-as-prompt`](https://github.com) skill:

- **Subject**: `<type>(<scope>): <imperative>` — types are `feat`,
  `fix`, `refactor`, `test`, `docs`, `chore`, `build`, `ci`, `perf`.
  Scope is optional but encouraged.
- **Body**: prose (not numbered list) structured as
  - `WHAT:` one line describing the action and its object, no
    implementation detail.
  - `WHY:` the motivation — bug, requirement, or design tradeoff.
  - `HOW:` the strategy, compatibility, verification, risk.
- **Trailers** (the lore protocol): `Constraint:`, `Rejected:`,
  `Confidence:`, `Scope-risk:`, `Directive:`, `Tested:`, `Not-tested:`.
  Use `Rejected:` to mark alternatives future agents must not
  re-explore. Use `Directive:` for forward-looking warnings.
- **Footer**: any non-trivial commit on a feature branch ends with
  `Plan: .omo/plans/<slug>.md` pointing at the design record.

Example shape (from this branch's own `f1aa83f`):

```
fix(store): hydrate persisted stats on client mount so /result shows history after refresh

The `hydrateStats` action on the game store was dead code: ...
...
Plan: .omo/plans/result-stats-reload.md
```

## Atomic commits

One topic per commit. Each commit must build and test green on its
own — no WIP, no omnibus, no "drive-by" mixed in. Auto-emitted files
(`next-env.d.ts`, anything inside `<!-- BEGIN:nextjs-agent-rules -->`)
get their own chore commit so a future bisect lands on the cause, not
on the noise.

## Design records (plan files)

Non-trivial work writes its design record to `.omo/plans/<slug>.md`
before the implementation commits. The plan file is the home of the
"why this option, not that one" reasoning, the must-not-have
guardrails, and the commit/footer convention the implementation will
respect. The first commit that ships the work cites the plan via the
`Plan:` footer. Patterns already on the branch:

- `.omo/plans/win-cheer.md` (cheer feature)
- `.omo/plans/result-stats-reload.md` (stats-hydration bug fix)
- `.omo/plans/agents-md-contribution-guidelines.md` (this section)

## Pull-request size

Keep PRs under **500 LOC of code** and **10 code files**. Excludes
docs, generated files, and lockfiles. If a task exceeds that, split
by layer, by feature component, or by refactor-vs-feature (the
cal.com/cal.com `agents/agents.md` pattern).

## Repository conventions

This file is the AI-agent entry point; `CLAUDE.md` is a one-line
`@AGENTS.md` include for Claude Code. The layout mirrors the patterns
used by well-known Next.js repositories:

- [vercel/next.js](https://github.com/vercel/next.js) — `AGENTS.md`
  holds the codebase tour and commands; `CLAUDE.md` is a symlink to
  `AGENTS.md`; `contributing.md` is a short entry pointing at the
  `contributing/` directory of focused guides (triaging, linting,
  release channels, PR descriptions).
- [supabase/supabase](https://github.com/supabase/supabase) —
  `AGENTS.md` is a monorepo tour + commands + skills pointer; per-app
  `AGENTS.md` files live under `apps/<name>/AGENTS.md`; conventions
  and CI gates are spelled out in the top-level file.
- [calcom/cal.com](https://github.com/calcom/cal.com) — `AGENTS.md`
  carries `Do` / `Don't` rules, PR size guidelines, and a `agents/`
  directory of supporting docs.
- [shadcn-ui/ui](https://github.com/shadcn-ui/ui) — `CONTRIBUTING.md`
  with a `.commitlintrc.json` enforcing the conventional-commit
  format at CI time.
- [documenso/documenso](https://github.com/documenso/documenso) —
  `AGENTS.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, and a
  `commitlint.config.cjs` as a baseline.

The common shape: an `AGENTS.md` for AI tooling, a
`CONTRIBUTING.md` for humans (often short and a directory-pointer),
a `CODE_OF_CONDUCT.md`, and a commit-message linter. We currently
ship only the first two (`AGENTS.md` and `CLAUDE.md`); a follow-up
PR may add `CONTRIBUTING.md` and commitlint once the convention
above has been observed for at least one release cycle.

## Verification gate

Before a commit is considered done:

- `pnpm vitest run` — must be 100% green (currently 67/67).
- `pnpm typecheck` — clean.
- `pnpm lint` — clean.
- `pnpm build` — must succeed (Next.js route count unchanged for
  pure docs commits).
- Browser QA scripts (`tests/qa/*.mjs`) — relevant ones for the
  touched surface must PASS. Currently exercised: hydration-check,
  audio-probe, audio-cheer, audio-confetti-qa.
