## 二、经验条目全录（13 条）

每条含：场景（本次对话事实锚点）/ 做法（可复用操作序列）/ 三条件映射（长期效应固化、信任提升、免盯梢机械化）/ 落点。

### 1. 首跑绿才算收口（rerun 绿与 bypass 不算数）

- **场景**：PR #18 首跑红连揭两处真问题（rooms-race 漏 `BASE_URL`、offline 探针违 BR-1）；修复提交后存在「rerun 到绿」与「admin bypass 强合」两条捷径可把红洗成绿。
- **做法**：确立收口判据——rerun 绿不算数、admin bypass 混过不算数，`run_attempt=1` 首跑全绿才算收口；PR #18 修复后按此执行，首跑全绿方 admin merge（`37326b9`）。
- **三条件映射**：长期效应=判据固化入 verification-gauntlet「2026-09-30 验证实践补充」+ anti-patterns L1-33；信任=CI 结论附 `run_attempt` 可由任何人独立查证，不依赖执行者自报，「合流前提=首跑全绿」可事后审计；免盯梢=required checks 本身机械强制，唯一人工位是「首跑」判定，可机械化（取 `run_attempt=1` 断言，候选 C6 邻接）。
- **落点**：报告§二 / gauntlet 实践补充 / anti-patterns L1-33。

### 2. CI 触发覆盖矩阵：无 PR 即全盲

- **场景**：CI 自 2026-09-15 移除 push trigger 后仅 `pull_request` 触发（ci.yml 历史可查）；rooms-race job 漏传 `BASE_URL`，自进 CI 起约 6.3 天从未绿过（`e1ea4b1` 09-24 进 CI → `a2a667d` 10-01 修复），触发面盲区 bug 沉默约 15.6 天（`ca7e6ad` 09-15 移除 push trigger → PR #18 首跑红 09-30）。主公亲令「不能让它就这样沉默的通过了」。
- **做法**：把「触发面」当作验证契约审视——每段改动先答「会被哪些门禁实跑」；不产生 PR 的改动面（dev 直推）= CI 全盲；结构性盲区如实入档（gauntlet Gap 6），是否立项 dev push 触发 CI 待主公裁，不擅自扩权。
- **三条件映射**：长期效应=anti-patterns L1-32 + gauntlet §3 Gap 6 入档；信任=盲区显式声明而非事后解释，汇报可先答「这段改动会被哪层实跑」；免盯梢=「ci.yml 触发器 × 分支 × job」矩阵机械对账即候选 C6，盲区出现即红。
- **落点**：报告§二 / anti-patterns L1-32 / gauntlet Gap 6 / 机械化 C6。

### 3. 探针红先本地复现定责

- **场景**：PR #18 首跑 offline 探针 A2a/A2b 红，嫌疑两分：业务回归 vs 探针过时。
- **做法**：本地复现定责三步——`pnpm build` + 起 hermetic server（`:3101`，L0-8 契约）+ 跑探针三犯复现；定责为探针期待停留 W3 时代、违反 BR-1 decree（弹框只在软导航转场弹），非业务回归；改合规软导航触发后本地 5/5 全绿再提交（`1b80a99`）。
- **三条件映射**：长期效应=「本地复现定责法」入 gauntlet 实践补充，探针过时形态入 L1-34；信任=定责结论可被他人在本地独立复跑证伪，不把探针红笼统归为 flaky；免盯梢=build + serve + probe 装配可做成一键 harness（与候选 C7/C8 同族的脚本化前置）。
- **落点**：报告§二 / gauntlet 实践补充 / anti-patterns L1-34。

### 4. 观察争议用代码取证三证裁定

- **场景**：匿名行决策卡前提（anonymous 计划的立论基础）被主公测试观察质疑——书面卡面与主公观察冲突，谁对？
- **做法**：代码取证三证——① `registerOrLoginRoom` 自起源 commit 一直补建（git 历史取证）；② 函数体与决策日 HEAD 空 diff；③ vitest 55/55 钉行为。据此裁定「主公的观察是对的，卡面前提被推翻」，如实入档，anonymous 计划终裁 ARCHIVED。
- **三条件映射**：长期效应=三证模式（git 历史 / 空 diff / 测试钉 seam）沉淀为本条目，复用于一切「文档断言 vs 实况」争议；信任=不护书面卡面、以代码为最终事实源，主公观察优先于档案结论；免盯梢=「文档断言 ↔ git 实况」对账可机械化（候选 C9 扩展面）。
- **落点**：报告§二 / 机械化 C9。

### 5. 换人独立复核 + 未验证边界显式标注

- **场景**：「战报上传 404 会显示报错吗」——核实员已有结论，仍派独立复核员另查。
- **做法**：复核员抛开核实员结论自行读码 + vitest 48/48 钉 seam 独立得出结论；对结论边界诚实标注「浏览器级时序系代码推断，未实跑探针」，不冒充已验证。
- **三条件映射**：长期效应=换人复核 + 边界标注入本条目（dispatcher-playbook 换人复核传统在验证场景的实证）；信任=复核独立性可审计（两条证据链分开）、「未验证」明示不遮丑；免盯梢=「已实跑 / 代码推断」可做成为汇报结论的必填字段，一眼可判。
- **落点**：报告§二 / §五盲区 1。

### 6. 生产设施操作 = 明示授权 + secret 不回显

- **场景**：cron 上线需直接操作 vercel CLI 触达生产设施。
- **做法**：主公明示授权（「vercel cli 可以你直接操作吗」）后才动手；link / env add / crons ls 全程 secret 值不回显、不入对话；操作逐条留痕可复盘。
- **三条件映射**：长期效应=生产边界两阶段（明示授权 → 操作留痕）入 gauntlet 实践补充（部署操作细节归 operations.md 辖域，本报告只留引用不重复事实）；信任=secret 零泄露可由对话记录直接审计，越权零发生可验证；免盯梢=操作前「授权留痕」可模板化（票面字段：授权人 / 授权语 / 操作清单）。
- **落点**：报告§二 / gauntlet 实践补充③。

### 7. 上线生效 = 状态迁移链 + 两态对照亲见

- **场景**：PR #18 合流（`37326b9`）后 Vercel 自动部署，「上线生效」需要证据而非推断。
- **做法**：轮询亲见 404→401 状态迁移（~40s 上线）；两态对照——裸请求 401、带 secret POST/GET 均 200，亲见后才写「生效」。PR #17（Dependabot 6 包）approve 后被 stale 门拦，按 #16 先例 admin 合入（`e31e8a9`）。
- **三条件映射**：长期效应=「生效」判定=状态迁移链 + 两态对照，入 gauntlet 实践补充③；信任=证据是响应码序列，可复跑可复核，不写未亲见的状态；免盯梢=部署轮询 + 两态 curl 可脚本化（候选 C7 的直接形态）。
- **落点**：报告§二 / gauntlet 实践补充③ / 机械化 C7。

### 8. 测试前缀造数边界实证 + 误差不粉饰

- **场景**：TTL 边界实证，主公令「各种情况的都造一点，反正你想看的边界情况都放上去嘛，然后看一下实际情况跟你的预期是否符合」。
- **做法**：`game_stats.updated_at` 为 epoch 毫秒（drizzle `timestamp_ms`）钉实后，zz-ttl-probe 前缀造 9 条边界行（只碰测试前缀、真实数据零接触）；手动 purge `deletedCount=5`（含库内 2 条真实过期陈货）、留 3；「正好 30 天」的行也被删——深究为 purge 晚于造数 40 秒、cutoff 推进，行为正确、系预期表设计误差非 bug，如实向主公报告不粉饰。
- **三条件映射**：长期效应=「造数-触发-对照」模式沉淀（候选 C8 可脚本化复用）；信任=误差如实披露并给出根因（40 秒窗口），不为结论好看而修饰预期表；免盯梢=造边界行 + 手动触发 + 删留名单对照全流程可脚本化（C8）。
- **落点**：报告§二 / 机械化 C8。

### 9. 定时任务两阶段验证 + 预埋必过线探针

- **场景**：cron 定时器一天只有一次真实触发机会，「定时生效」无法当场闭环。
- **做法**：两阶段设计——今天手动 purge 验删除逻辑、明天 cron 验定时器；补造「明日必过线」行，让次日 Cron Logs 必有 `deletedCount≥1` 证据（预埋必过线探针，防「日志无事发生」无从判定的哑验证）。
- **三条件映射**：长期效应=两阶段设计入本条目，次日证据锚点已预埋在库；信任=次日验证有预埋证据，不靠记忆或「应该跑了」；免盯梢=次日日志检查可自动化（C7：crons ls + Cron Logs `deletedCount` 断言）；本次次日验证尚未发生（§五盲区 2）。
- **落点**：报告§二 / §五盲区 2 / 机械化 C7。

### 10. 状态回写前现查钉实

- **场景**：十档状态回写（决策卡 / 台账 / 状态线）最容易凭记忆写「已完成 / 已上线」。
- **做法**：每处落笔前 git / vercel CLI / curl 现查钉实（hash、部署状态、端点响应），不凭记忆写状态（`2bf1663`、`b8e3e0c`）。
- **三条件映射**：长期效应=「现查钉实」纪律入本条目，与 dispatcher-playbook「机器锚点优先」同哲学；信任=回写的每个状态可逐项对回取证命令；免盯梢=「文档状态 ↔ git / 部署实况」对账可机械化（C9 直系场景）。
- **落点**：报告§二 / 机械化 C9。

### 11. 打标判据 = 验证闭环，tag 不擅自推远端

- **场景**：九三零波收口，是否打 dev-stable 标需要判据。
- **做法**：主公亲判「刚才我们验证了它确实生效了」——打标判据=验证闭环，而非「活干完了」；tag dev-stable-20260930 → `2bf1663`，本地 tag 不推远端，push 与远端发布权保留主公。
- **三条件映射**：长期效应=打标判据入本条目，打标时点与指向 git 可查；信任=打标由主公判词触发、远端发布权不在执行者手里；免盯梢=tag 存在性 / 指向 / 是否已推远端三条 git 命令一眼可判。
- **落点**：报告§二。

### 12. 工具坑修环境根因，不绕门禁

- **场景**：验证工具链自身连环坑：ZCode shell node16 跑 commit-msg hook 崩；`/usr/local/bin/pnpm` v7 违 engines；commitlint 两硬规则（footer 行≤100、subject 禁拉丁开头）；heredoc 结束符带尾巴会把 shell wrapper 灌进 message；gh API 偶发 EOF。

### 13. 已知缺陷显式报错，错误路径也验收

- **场景**：「战报上传 404 会显示报错吗」——已知缺陷的处置哲学，主公定调「我们直接返回报错，显示提示没有问题」。
