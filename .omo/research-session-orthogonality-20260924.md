## 一、主公主张的忠实转译与精确化

### 主张一：Session 单一事则

> 「一个 Session 就应该只做一件事，如果做不好，那应该再拆分的足够小，小到足够一个 Session 的对话能完成为止。」

精确化：Session 的计量单位不是时间或任务数，而是**上下文容量**。一件事的定义 = 「所需的全部上下文（代码面 + 决策史 + 被检对象）装得进一个干净会话且不会互相稀释」。做不好 = 上下文互相稀释或装不下 → 继续拆，直到每块都是单会话完整闭环。这与 wayfinder 的机制完全同构：**每 session 只解决一张工单**（wayfinder-analysis-report §六.4「每 session 一张票是极好的上下文卫生」）+ **按 100K token 会话裁票**（报告 §三）。

### 主张二：探索先行，执行后置

> 「做这之前我们需要做足够多的探索，让后面的工作只剩下执行。」

精确化：对应 wayfinder 的 **Plan, don't do**（上游 11-13 行：*"The pull to just do the work is usually the signal you've reached the edge of the map and it's time to hand off"*——想直接开干的冲动正是该移交的信号）与**战争迷雾判据**（§三：*"The test is whether you can state the question precisely now — not whether you can answer it now"*）。分工：
- **WayFinder = 跨会话探路**：把大而模糊的想法物化为「地图 + 决策工单」，跨会话逐张消化，迷雾逐渐清晰，直到「后面的工作只剩下执行」（路已清晰、票已清零）。
- **GrillMe/grilling = 单会话拷问原语**：每轮把当前全部可问的问题一次抛出（编号 + 推荐答案），答完重算前沿——它是 wayfinder 绘图与解题共用的底层技能（报告 §七：grilling 是 grill-me/wayfinder/triage 共用底层）。
- 本仓接线：`$omo:ulw-plan` 之前的探索阶段 ≈ wayfinder 绘图模式；plan 文件 ≈ 地图（Decisions so far ≈ plan 的裁决记录节）。**与既有 omo 流程是兼容而非替代**。

### 主张三：任务正交性 = 按共同上下文拆分，而非按任务内容拆分

> 「多 agent 多 session 调度是根据共同的上下文来拆分的，而不是任务内容来拆分的。对抗性检查这种确实上下文是正交的，但是他们运用的检查方式是不同的，这个时候我认为就应该隔离开来，多出来的上下文开销，我认为是有必要的。」

这是本仓调度学的一次**判据升级**：旧判据「按任务内容/文件面拆票」（§rooms-race 报告旧文也用了「文件面互不相交」表述）只回答了「能不能并行」，没回答「该不该隔离」。主公判据回答的是后者。精确化为 2×2 判定矩阵：

### 正交性判定矩阵（本次探索的核心产出）

| | 工作/检查方式**相同** | 工作/检查方式**不同** |
|---|---|---|
| **共享上下文** | **同 session 串行做**（省上下文重建税；例：调度者收尾微修 `848aa9b`——六条 findings 的完整语境在一个脑子里，拆出去反而要重建） | **强制拆 fresh session——仅限对抗性评审**（主公修正 09-24：强制力的来源是评审独立性——模型自身有偏见与漂移，必须 fresh session 消除；「自我确认不是确认」。非对抗场景的异方式——如同会话内实现后自测——不强制拆，但关键裁决仍应交外部新鲜眼睛） |
| **上下文正交** | 可并行（为墙钟速度；例：本波 4 修复席——worktree + 不相交文件面，合并反而无意义） | **隔离并行的最大价值区**（例：本波 4 交叉审——四种检查镜头各占一个干净会话，即使被检对象有重叠也不合并） |

**对「对抗性检查隔离」的正当性论证**（为什么多出来的上下文开销是必要的）：检查的价值在于独立性——LLM 语境下，一个会话内的多个镜头会互相锚定（先入发现会 out-vote 后入镜头，同 L1-29 的 15-call 衰减机制）；为省一份上下文把两个镜头塞进一个会话，买到的是「更便宜但更弱」的检查。主公论断把这个权衡显式化：**检查强度 > token 成本**，凡属验证性工作默认隔离。

## 二、本波实证复盘（用新判据检验已发生的调度）

| 4 修复席并行（worktree 隔离、文件面不相交） | 正交 + 方式同 → 并行 | ✓ 正确（墙钟收益；且票间本就无共同上下文可共享） |
| 4 交叉审各占独立 fresh codex（rev① R7 语义 / rev② 语义等价 / rev③ 逐项闭环 / rev④ 御裁合规总审） | 正交 + **方式不同** → 隔离并行 | ✓ 正确，且是矩阵右下最大价值区的实例——rev④ 的「整合视角」若塞进 rev① 的会话，会被票①细节锚定 |

| 【反例警告】rev② 若顺带审 rev① 的 R7 | 方式不同却同 session | ✗ 会犯矩阵右上错误（锚定 + 上下文混装） |

## 三、与 wayfinder 体系的对齐表（引用 wayfinder-analysis-report）

| 主公主张 | wayfinder 对应机制 | 差异/增强 |
|---|---|---|
| Session 单一事则 | 每 session 一票（SKILL.md:80，上游 research 例外）+ 100K 裁票（SKILL.md:42） | 主公增加了「做不好再拆」的递归细则；wayfinder 的裁票启发值是静态的，主公判据是动态的（做完才知道装不装得下，装不下即拆） |
| 探索先行，执行后置 | Plan, don't do（上游 11-13 行）+ 雾区禁预切片（SKILL.md:71-74：「能精确陈述问题才立票」） | 完全同构；主公的「让后面的工作只剩下执行」即 wayfinder 的终态「路已清晰、票已清零」 |
| GrillMe 单会话 / WayFinder 跨会话 | grilling（单会话访谈原语）/ wayfinder（跨会话地图） | 两层架构（user-invoked 编排 / model-invoked 纪律，报告 §七）为本仓「调度者层 / 执行席层」提供同构参照 |
| 任务正交性判据 | （wayfinder 无此机制——它管拆多细与何时立票） | **主公原创**：wayfinder 回答「拆多细、何时立票」，正交性判据回答「哪些票该隔离、哪些该同 session」——两者组合才完整 |

## 五、主公裁决（2026-09-24）

1. **矩阵获准，附修正**：右上格「共享上下文 + 方式不同 → 必须拆」**仅限对抗性评审**——强制拆的理由是模型自身有偏见与漂移，必须 fresh session 消除；非对抗场景不强制。
2. **T4 wayfinder 试点 = 本次 rooms-race 任务本身**——第一张地图已立：[plans/ulw-rooms-race-map-20260924.md](plans/ulw-rooms-race-map-20260924.md)。
3. **T2/T3 立即融合进计划文件**（Session 级拆分），正式落 dispatcher-playbook 作为地图内的执行票（T-E）。
4. T1 rooms-race 票拆分修订随地图执行（地图内 T-B1/B2/D 的划分即修订结果）。

本文件此后作为地图的证据资产被引用；方法学的仓库资产落点为地图内 T-E 票（dispatcher-playbook 新节）。
