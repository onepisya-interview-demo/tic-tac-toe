结论：R6/R8 当时零远程触发点（本地防线全押钩子安装＋手动 verify-all）；底数干净（range 85/85、branch 506 笔 fail=0 双绿）。推荐 A+：独立 commit-audit.yml 三触发＋fetch-depth:0＋advisory 起步——push→dev 面给 R6 第一个远程自动触发点、覆盖 dev 直提主缺口；零依赖 job 约 30-60 秒、公共仓不计费；删文件即回滚。
发现一（触发面）：commit-msg 结构性不跑 R6（commit-audit.mjs:312-313 源注，--message-file 面）；CI 无 audit job；pre-push 只做法令守卫；R6 唯一执行面＝手动 branch/range 或 verify-all ⑤层，而 verify-all 自身无自动触发点。R8：新克隆未重装 pre-commit 即失效（钩子在 .git/ 内 git 永不跟踪，重建源 rollout §3.6）；CI 无 R8；--message-file 面 by design 不跑 R8（:154-156）。
发现二（PR 机理，severity high）：PR 事件 checkout 的是 merge ref（官方 events 文档：GITHUB_REF=refs/pull/N/merge）；checkout 默认 fetch-depth=1 时只 fetch 触发 ref 本身，origin/main 不存在→--range origin/main..HEAD 直接 git exit 128 崩溃（已在 /tmp depth=1 克隆实证复现：fatal: ambiguous argument）。裸 git fetch origin main 在 single-branch 浅克隆下也不建 origin/main（本机实证）。配方＝fetch-depth: 0（getRefSpecForAllHistory 全量 refspec，源码级保证 origin/main 必在；仓仅 5.14 MiB 秒级）。base.sha 语法兼容 --range（commit-audit.mjs:174 原样传 git log）但是创建时点快照可落后（PR #22 实例 afad8df≠main tip），首选 origin/main（与 verify-all ⑤层同款命令字符串）。
发现三（ruleset 实况，2026-11-01 gh 快照）：仓 PUBLIC；main-gate/main-redline 均 repo 级（非 org——org 层因 gh 缺 admin:org scope 404 无法证伪，如实标注）。main-gate（id 23195249，active，~DEFAULT_BRANCH）＝required_status_checks 11 项，与 ci.yml 各 job 的 name: 显示名逐字相等（311d91c 修复后形态；311d91c 教训：required checks 按精确字符串匹配，登记名必须是 job name: 值非 job id）。main-redline（id 23195170）＝deletion＋non_fast_forward，无 required checks、无审批门（旧称谓与实况互为颠倒，后续文档一律写「repo ruleset」）。dev 分支无保护。新 job 阻断合并须 PUT rulesets/23195249 追加其 name: 值（草拟名 Commit audit (commit-audit --range)）→12 项；本波不做。Dependabot PR 预期 PASS（botAuthored 豁免 R3-R5/R7，R1/R2 仍强制，commit-audit.mjs:93-99/236-238，subject 恒 Conventional）；squash 产物在 range 语义下永不入集（main 可达即被排除，第四类豁免天然闲置）。
